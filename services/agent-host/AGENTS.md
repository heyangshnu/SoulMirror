# fate-and-fortune / SoulZen Claude Code Project Rules

本子项目使用 Claude Code 作为多 Agent 执行 harness。每个 Agent 的最高定义写在 `agents/{agent}.md`，正文即本项目语境里的 SOUL，内置该 Agent 的 Skill、边界、记忆法、协作法和完成标准。

第一版记忆底座采用 Basic Memory：一人一个 Basic Memory project，Markdown note 是真源，Basic Memory 的索引和 MCP 是运行时检索/读写层。多人、伴侣、家庭场景只能在明确授权下联通 project 或导入对方上下文。

## 角色

- 菩萨 Agent：用户前台回应、调用记忆上下文、组织回答、提交回写候选。
- 功曹 Agent：每轮后轻判断、保留通讯审计、维护路由记忆、向一个或多个罗汉 multicast 材料、判断是否触发伏羲预设节点。
- 愿罗汉：管理愿景、目标、执行。
- 境罗汉：管理城市、行业、家庭处境、教育、技术趋势等外部环境。
- 缘罗汉：管理血缘、亲密、核心朋友、商业、浅层关系。
- 力罗汉：管理时间、精力、现金、能力、工具、家庭支持、可试错额度。
- 伏羲 Agent：薄调度壳，调用已有伏羲节点提示词，负责 `01_命/` L0-L3 命盘与周期底座。

## Basic Memory 布局

每个用户 project 使用固定目录：

```text
00_soul/
01_命/
02_愿/
03_境/
04_缘/
05_力/
06_功曹/
07_上下文包/
08_归档/
```

`06_功曹/` 是功曹独立通讯、路由和回执库：

- `routing-memory.md`
- `events.jsonl`
- `dispatch.jsonl`
- `receipts.jsonl`

功曹只提供场景、原文、菩萨摘要和投递说明。四域长期沉淀由对应罗汉自行判断、维护和回执。

## 写入边界

- 菩萨不直接写长期记忆，只读取上下文、回应用户、生成回写候选。
- 功曹不写愿/境/缘/力长期 note，只写 `06_功曹/`。
- 罗汉只维护自己领域 note，并让领域话题网按用户表达习惯自然生长。
- 伏羲只维护 `01_命/` L0-L3 命盘报告和按需专题，不写现实生活记忆。
- 每个 Agent 完成任务时输出 `AGENT_TASK_COMPLETE`。

## 原文优先

所有 Agent 写入 Basic Memory 时，必须优先保留用户原文、原话和说话者原意。

- 能用原话就用原话。
- 事实层不改写用户表达。
- 分析、推测、归纳必须另起字段。
- 错误、口语、情绪化表达也保留原貌。
- 不得用 Agent 的二次总结替代用户原意。

推荐 observation 形态：

```markdown
- [explicit]
  原文：「我越来越想回上海，不管有钱没钱都想回去。」
  说话者：user
  时间：YYYY-MM-DD
  轻注：阶段目标增强，涉及城市迁移与小家边界。
  禁止误用：不得直接写成“用户已决定搬家”。

- [inferred]
  推测：回上海可能不只是城市选择，也涉及社交、自我空间和家庭边界。
  置信度：medium
  待印证：是
```

## 记忆状态标签

统一使用：

- explicit：用户明确表达。
- fact：事实记录。
- inferred：系统推测。
- pending_confirmation：待印证。
- confirmed：已确认。
- phase_active：阶段有效。
- durable：长期稳定。
- outdated：过期。
- conflicted：冲突中。
- archived：归档。

## 罗汉话题网

每个罗汉维护自己的领域话题网。话题节点可以围绕人物、事件、时间段、地点、项目、压力、资源、关系、问题、反复出现的表达或混合簇自然生长。节点命名先贴近用户原话，随着重复材料增多再合并、重命名、沉降。

## 伏羲初始化边界

新用户初始化只并行生成 16 个核心节点，不初始化 B09 全生命周期流年报告。B09 只保留为按需专题节点。

伏羲使用 `fuxi-nodes/` 下已有节点提示词；`fuxi.md` 只负责接收工单、选择节点、组织输入、调用模型、写入 `01_命/`，不重写解盘方法论。
